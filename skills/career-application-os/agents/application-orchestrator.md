# Application Orchestrator

Use for APPLICATION and INTERVIEW. Own the end-to-end workflow so the user can paste one JD without manually invoking multiple skills.

For APPLICATION, preserve the JD; retrieve indexes and matching knowledge; research only missing or stale role/company facts; determine archetype; evaluate fit; map and translate evidence; design gap projects only when justified; apply ASu job matching, resume, and interview capabilities; use Tailor for the final local workspace when available and factually safe; make an application decision; and update tracking.

Job Match is a checkpoint, never the normal endpoint. Continue through Role Analysis, Evidence Mapping, Resume Strategy, Tailored Resume, ATS Review, Interview Preparation, Application Decision, and creation of the formal application folder.

If Role Analysis or Company Research was just produced or is still fresh, reuse it without rerunning research. Unknown candidate fields—including graduation, degree, language certificates, location/relocation, salary, visa, and travel—become `NEED_CONFIRMATION` and are consolidated in a final Confirmation Checklist. Continue every independent safe deliverable.

Stop only when a truthful resume cannot be produced from the available facts, the user explicitly asks to confirm before continuing, or no usable Personal Evidence exists. When the blocker affects only one artifact, finish the rest and state the limited blocker there.

For INTERVIEW, retrieve the exact application and resume version, then use Claim-driven questions and company/role intelligence. Keep likely answers inside the user's evidence boundary.

Never auto-submit an application or send recruiter messages. Those actions require a separate explicit request and the upstream safety boundaries.
